# AlgoPath submission checklist

Complete this checklist before submitting the project.

## Repository

* [ ] The GitHub repository is public.
* [ ] `index.html` is in the repository root.
* [ ] The README explains the project, features, technologies, and structure.
* [ ] The README contains the final deployed link.
* [ ] The latest version of every file was uploaded.

## Application

* [ ] The home page loads without a blank screen.
* [ ] The layout works on desktop and mobile widths.
* [ ] Every navigation link moves to the correct section.
* [ ] All four difficulty filters work.
* [ ] Topic search updates the visible cards.
* [ ] Every **Explore topic** button opens the correct information.
* [ ] A topic can be marked as completed from its card.
* [ ] A topic can be marked as completed from the details dialog.
* [ ] The progress percentage and checklist update correctly.
* [ ] Progress remains after refreshing the browser.
* [ ] Reset progress clears the saved topics.
* [ ] The mobile menu opens and closes.
* [ ] External practice links open correctly.

## Browser checks

* [ ] Test the deployed page in Chrome or Edge.
* [ ] Open the browser developer tools and select the Console tab.
* [ ] Refresh the page and confirm there are no red errors.
* [ ] Test at least one mobile size in the device toolbar.
* [ ] Open the deployed link in a private window to confirm it is public.

## Tier 1 points to understand

Be ready to explain these parts of the project:

1. The HTML sections and why semantic tags such as `header`, `main`, `section`, and `footer` were used.
2. How CSS Grid changes from three columns to two columns and then one column.
3. How the filter compares each topic difficulty with the active filter.
4. How search checks the title, description, and level text.
5. How a `CustomEvent` moves an action from a Web Component to `app.js`.
6. How localStorage saves an array of completed topic IDs.
7. Why the project has no backend or user account.

## Chingu form

* [ ] Tier 1 Beginner is selected.
* [ ] The public repository URL is entered in the GitHub field.
* [ ] The GitHub Pages link is entered in the deployed application field.
* [ ] The applicant can explain the main project features and code flow.
